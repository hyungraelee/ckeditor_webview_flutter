## Source distribution

The optional builder in `tool/ckeditor_builder/` resolves requested CKEditor versions in the
consuming application's build environment. It preserves installed upstream
license texts in the generated HTML and `dist/THIRD_PARTY_NOTICES.json` cache
artifact. The app's `ckeditor_webview_flutter.lock` identifies the resolved
engine and npm dependencies. These generated records must not be treated as
completion of corresponding-source distribution for that app release.

The editor entry point, build configuration, and exact dependency lockfile are
included in `tool/ckeditor_build/`. See [CONTRIBUTING.md](CONTRIBUTING.md) for rebuild instructions.
Those build recipes and upstream links do not by themselves replace any GPL
obligation to provide complete corresponding source when distributing a
compiled bundle.

Source downloads for package **0.1.0**, including the bundled CKEditor **41.4.1**:

- [Versioned source archive](https://github.com/hyungraelee/ckeditor_webview_flutter/releases/download/v0.1.0/ckeditor_webview_flutter-0.1.0-sources.tar.gz)
- [SHA-256 checksum](https://github.com/hyungraelee/ckeditor_webview_flutter/releases/download/v0.1.0/ckeditor_webview_flutter-0.1.0-sources.tar.gz.sha256)

This separate archive preserves package sources, upstream modification sources,
notices, and pinned build inputs. It covers the bundled editor, not optional
engines generated by a consuming application. The automatically generated
GitHub repository snapshot does not contain these third-party source inputs.

The bundled-editor inventory, inspected source provenance, and outstanding
release work are documented in
[the release source audit](tool/release/README.md). The inventory is not a
source archive. Prepare and verify the versioned archive with
[the maintainer source tools](tool/release/SOURCE_ARCHIVE.md). The
[manual release procedure](tool/release/MANUAL_RELEASE.md) requires the source
downloads to be publicly accessible before uploading the package to pub.dev.

The [integration licensing review](tool/release/INTEGRATION_LICENSE_REVIEW.md)
compares pinned public integration examples with official licensing guidance.
It records source-access retention and component-specific review requirements;
another integration's license does not establish permission for this distribution.
